## 2. Issue 生命周期

| 阶段 | 状态 | 动作 |
|---|---|---|
| 提出 | Open | 写清场景、目标、验收标准 |
| 排期 | Backlog / Todo | 决定优先级和负责人 |
| 开发 | In Progress | 从 main 开 feature 分支 |
| 评审 | In Review | 提 PR,等待 CI 和 Review |
| 合并 | Done | PR 合并（由人类执行）,自动关闭 Issue |
| 验收 | Verified | 按验收标准在公开 URL 上确认 |

**追踪规则**:分支名带 Issue 号,PR 描述写 `closes #<编号>`。

### US-2 结构展签索引（原"结构目录与检索"） · 优先级 P0 · 状态: 已定稿（2026-11-27:先按用户要求删除旧搜索框与目录折叠开关、左栏改为展签;随后去掉纸卡外观,索引透明底直接切进黑色帷幕、结构名取解剖色;再去掉「图一 · 心脏整体观」标题,在顶部横线加回**无边框结构搜索**——提示语「如：左心室 / left ventricle / LV」,支持编号或中英文名,并让索引/搜索选中把 3D 部件转到正面追光）

我想要 在聚光灯舞台左侧的透明索引上,按编号、中文名或斜体英文名直接点选结构,或在顶部横线输入编号/名称定位,
以便 不必记忆系统命名也能定位结构,同时保持"暗场—聚光—展品—展签"的完整场景。

验收标准:
- AC1: Given `public/assets/structures.json` 至少含 8 个结构,Then 索引按冻结标签 1–9 列出编号、中文名与斜体英文名,中文名以该结构的解剖配色呈现,点选任一条目即选中该结构;顶部是一条无边框搜索框,提示语为「如：左心室 / left ventricle / LV」,输入单个编号 1–9 或中英文名即选中对应结构,点索引条目后框内同步显示当前编号,从名称搜索选中时保留用户输入,关闭详情后清空。
- AC2: Given 已选中结构,Then 选中态只有两处变化:中文名加粗、编号方块由空心变实心（不加色条与底色）。
- AC3: Given 已收录但网格缺失的结构,When 页面加载,Then 该结构被标记为不可用并从索引剔除,展签底部注明原因。

- AC5: Given 键盘与读屏,Then 每个条目是可聚焦按钮,选中状态经 `aria-pressed` 播报,展签整体有可读名称,搜索框有可读标签。
- AC6: Given 从索引或搜索框选中结构,Then 整颗心脏绕解剖上下轴在 800 ms 内转到该部件正对相机,聚光灯心同步沿同一转角跟到部件包围盒中心并收窄锥角;Given 直接在 3D 里点部件,Then 保持当前机位,只点亮与追光,不强制转向。

### US-5 整颗心脏轻量 3D · 优先级 P0 · 状态: 已完成（2026-11-24，M4b 把"单结构网格面板"换成整颗心脏：9 个部件 GLB 同场景自动拼合,悬停报名称、单击选结构、非选中半透明;`HeartModel` 懒加载 chunk 642.89 kB,首屏 JS 仍 232.47 kB;无 WebGL 局部降级有 3 条用例。2026-11-26 追加：初始机位对齐用户截图的正前偏上 10°、距离 2.5,`camera.up` 对齐解剖 +z;整颗心脏 72 次/分双搏动,可暂停,减动效偏好下默认暂停）

作为 **医学学习者**,
我想要 在同一个 3D 场景里看到整颗心脏,并能点选其中的任一部件,
以便 同时理解单个结构的形态和它在整体里的毗邻关系。

验收标准:
- AC1: Given 页面载入完成,When 9 个部件 GLB 加载结束,Then 它们按世界毫米坐标自动拼合成一颗完整心脏（不做任何配准）,以固定截图机位直立呈现,可拖拽旋转、滚轮/按钮缩放、一键复位视角（复位回到初始截图机位）。
- AC2: Given 鼠标悬停在某部件上,When 移动,Then 状态行显示该结构的中英文名;Given 单击该部件,Then 信息卡与三视图同步切到该结构,其余部件降为半透明。
- AC3: Given 无 WebGL 或某个 GLB 取不到,When 渲染,Then 只有 3D 区域降级为提示文字（含失败文件名）,检索、信息卡、三视图不受影响。
- AC4: Given 提交的 GLB 资产,When 检查体积,Then 单个文件 ≤ 2 MB,全部网格合计 ≤ 阈值（阈值记入 `PROGRESS.md`）。
- AC5: Given 加载完成且未暂停,When 观察,Then 整颗心脏以约 72 次/分的"扑通"双搏动轻微缩放（≤约 2.2%）,不出现部件接缝;Given 点击暂停,Then 立即回到基准缩放并保持静止;Given 系统开启减动效,Then 默认不自动搏动,用户可手动开启。

技术备注:
- Three.js 原生 + GLTFLoader + OrbitControls;`tools/asset_pipeline/surface.py` 写出的顶点是世界毫米,所以 9 个部件放进同一个场景即成型,且与 US-4 的切面同源。
- `React.lazy` 把 Three.js 整体留在懒加载 chunk 里;`role=button` 之外的 3D 交互（透明度、拖拽阈值判定）抽成 `src/data/heart.ts` 纯函数,不依赖 WebGL 也能单测。
- 相邻部件表面穿插是真实解剖（主动脉穿出左心室腔口）,拼合后必然互相插入,不是错位;半透明层必须关 `depthWrite`,否则前面的部件会把后面的整块挡掉。
- 解剖坐标系是 +z 为上,相机 `up` 必须对齐 +z 才能得到直立位;心跳只缩放整颗 root,并同步平移保持旋转中心不变,约 30 帧/秒节流,暂停/卸载时取消 rAF。

### US-6 示意资产生成管线 · 优先级 P0 · 状态: 已完成（2026-11-24，BP3D 路线，本地门禁全绿）

作为 **项目开发者**,
我想要 一条可重跑、可审计的 Python 资产管线,
以便 三视图与 3D 网格来自同一份几何,并且换机器也能重建。

验收标准:
- AC1: Given `assets_raw/` 中已放置筛选后的 BP3D OBJ 文件,When 运行管线,Then 依次产出:标定对齐后的网格、统一标签体素、三视图底图+overlay、GLB、`structures.json`。
- AC2: Given 管线运行完成,When 检查产物,Then 所有结构共用同一体素网格（同 shape、同 affine）,三视图与 GLB 的空间关系一致。
- AC3: Given 单元测试覆盖网格加载、体素化、切面取层、`structures.json` 校验四类纯函数,When `pytest --cov-fail-under=80`,Then 通过。
- AC4: Given 任一结构的 OBJ 缺失或坐标系不匹配,When 运行,Then 明确报出该结构名并跳过,而不是产出错位资产。
- AC5: 管线**不读取** `D:\codex\project002_**` 下任何路径,全部输入路径通过参数或 `assets_raw/` 提供。

技术备注:
- **一律在 conda env `tianchi`（Python 3.11.18）执行**，不碰研究环境 `FMA`。依赖见 `requirements-asset.txt`（numpy 2.4.6 / scipy 1.17.1 / scikit-image 0.26.0 / pillow 13.0.0）与 `requirements-dev.txt`（pytest 9.2.0 / pytest-cov 7.1.0 / ruff 0.17.6）。
- **不引入 trimesh**：OBJ 解析、体素化、`marching_cubes`、GLB 写出全部由 `tools/asset_pipeline` 纯 numpy 自实现，减少外部二进制依赖。

- BP3D 各部件共用一次均匀缩放 + 平移,实测轴向与本项目 `[左右, 前后, 上下]` 同号、无需翻转;仿射对位不再是不确定项。

## 5. 非功能需求

- **安全与隐私**:密钥只进 Secrets,不进 Git。**不发布任何真实病例影像**;页面资产全部为示意几何渲染或由教学标注体素合成的伪 CT,不接受用户上传影像。个人证件、成绩单、简历等材料不得进入本仓库任何目录。
- **可发布性**:静态产物,评委无需安装依赖、无需登录、无需下载压缩包。
- **可复现**:资产管线在干净 checkout + `assets_raw/` 输入条件下可重跑;`NOTICE.md` 记录每条命令。
- **可维护**:一个需求一小 PR,分支默认保留。
- **可测试**:检索逻辑、`structures.json` 校验、资产管线必须有单测;UI 有冒烟测试。
- **性能**:首屏资源（HTML/JS/CSS/目录 JSON）控制在可接受体积,网格按结构懒加载。
- **合规留痕**:许可判定、无法核实项、保守处置,全部写在 `NOTICE.md` 与项目书 §6,不靠口头说明。
